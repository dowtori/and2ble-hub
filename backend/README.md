# 친구추천 처리

프론트엔드: `dist/referral/`. 백엔드는 기존 캠페인 신청을 받는 동일한 Apps Script 웹 앱입니다. 일반 신청 A~J열 저장 로직은 유지하고, 저장 후 추천 대조를 실행합니다. 선정 여부 K열은 수정하지 않습니다.

## 소스와 배포

1. `npm test`를 실행합니다.
2. `npm run build:apps-script`로 `backend/generated/Code.gs`를 생성합니다.
3. 기존 Apps Script 편집기의 `Code.gs`를 생성본으로 바꾸고 저장합니다.
4. 최초 설정은 `setupReferrals`를 한 번 실행합니다. 기존 L열 선택지와 수동 메모를 보존하고, 양쪽 역할 선택지만 추가합니다.
5. 배포 관리에서 **기존 웹 앱 배포를 편집하고 새 버전**을 선택합니다. 웹 앱 주소·실행 계정·공개 범위는 유지합니다.

기존 편집기: https://script.google.com/home/projects/1PivNDK24YdgWoiAVNUVhoKKhPQbvInwzqTjy4FQ1Qug-14qHDR30-BgA/edit

정적 프론트엔드의 Git 푸시와 Apps Script 백엔드 배포는 별개입니다. 백엔드 변경 시 위 절차를 완료해야 실제 동작에 반영됩니다.

## 저장·대조

- 원본 문서: https://docs.google.com/spreadsheets/d/1T1i3U-lNK0yE0dv0L_adKKv5OOw5NY-BT8PGSDDyWYU/edit
- 원본 신청 탭은 이름 대신 gid `1002`로 찾습니다.
- L열: `초대를 한`, `초대로 들어온`, `초대를 한 · 초대로 들어온`. 셀 메모에 상대 계정, 등록·인정 상태, 추가 보상 근거를 기록합니다. 수동 메모는 유지합니다.
- `친구추천인`: 추천인 연락처와 핸들. 접근키 원문 대신 SHA-256 해시를 저장합니다.
- 추천인은 Instagram·TikTok 중 본인 계정 하나만 입력하면 친구 정보 입력으로 이동합니다. 추천인의 기존 등록 여부나 K열 선정 여부로 진입을 제한하지 않습니다. 일치하는 기존 신청이 있으면 이름·이메일·다른 계정을 연결하고, 없으면 입력한 계정으로 추천인ID를 생성합니다. 기존 등록 차단은 소개할 친구에게만 적용합니다.
- 화면은 `본인 확인 → 친구 정보 입력 → 이 친구 추천하기 → 해당 친구에게 보낼 링크` 순서입니다. 중간에 링크 복사나 추천 현황 화면을 끼워 넣지 않습니다. Instagram을 TikTok보다 앞에 표시합니다.
- 친구추천내역 C열 추천인ID의 셀 메모에도 추천인 이름·Instagram·TikTok을 기록하여 보상 귀속을 확인할 수 있습니다.
- `친구추천내역`: 친구 연락처·핸들, 등록 대조, 응답 행, 운영팀 참여 인정, 추가 리워드.
- 친구 핸들은 원본 G(TikTok)·H(Instagram)열과 플랫폼별로 대조합니다. @, 대소문자, 프로필 URL을 정규화합니다.
- 추천 접수 때 이미 등록한 계정과 본인 추천은 거절합니다. 이후 같은 참여자로 확인되는 복수 추천은 최초 접수 1건만 보상 대상으로 남깁니다.
- 일반 신청 저장 후 즉시 대조합니다. 원본 신청 또는 추천내역을 수동 편집한 경우 바인딩된 `onEdit`가 대조합니다. 추천인 현황 조회도 다시 대조합니다.

## 참여 인정과 보상

운영팀이 실제 게시물을 검수한 뒤 `친구추천내역` **J열 `참여인정`을 `인정`**으로 바꿉니다. 신규 등록과 해당 인정이 모두 있을 때에만 추천인에게 친구 1명당 2,000엔을 추가합니다. `선정`은 참여 인정으로 간주하지 않습니다. 추천받은 친구에게 추가 추천 보상은 지급하지 않으며, 기본 캠페인 리워드는 기존 조건을 따릅니다.

기프트카드 발송이나 금전 지급은 실행하지 않습니다. 기록된 추가 리워드를 최종 정산 때 반영합니다.

## 접근과 확인

추천인의 고유 ID는 입력한 SNS 종류와 정규화한 아이디에 연결됩니다. 다른 기기나 브라우저에서도 같은 계정을 입력하면 기존 ID를 재사용합니다. 브라우저에는 다음 방문 때 입력을 돕는 SNS 종류·아이디만 저장합니다. 이 입력은 보상 귀속을 위한 계정 식별이며, 승인 심사나 개인 추천 내역을 열람하는 로그인 기능이 아닙니다.

친구에게 보내는 링크에는 추천인과 친구를 연결한 무작위 추천ID(`?ref=...`)만 넣고 연락처는 넣지 않습니다. 친구는 추천 정보를 다시 입력하지 않고 캠페인 신청으로 이동합니다. 같은 추천인이 같은 미등록 친구를 다시 입력하면 기존 추천ID와 링크를 반환합니다. 기존 `?from=...` 링크와 접근키를 요구하는 현황 API는 호환성을 위해 유지하지만, 새 화면에는 현황을 표시하지 않습니다.

쓰기 요청은 POST만 사용합니다. cross-origin 응답 확인은 요청마다 생성한 무작위 128비트 ID로 캐시 결과를 조회합니다. JSONP 콜백은 정해진 이름 형식만 허용하며, 공개 조회에는 전체 명단·이메일·접근키를 반환하지 않습니다. 클라이언트는 응답 미확인 시 쓰기를 자동 재시도하지 않습니다.
